# 公众号采集与热榜

入口：设置 → 手机权限 → 本机 ADB → 公众号采集与热榜。

## 产品流程

先通过本机 ADB 的通知栏无线配对完成授权，启用微信 XWeb 调试，并在 DSH Custom 配置模型服务。
批量采集时，在微信打开“我关注的公众号”，回 DSH 选择每号篇数（默认 50）并点击“扫描我的关注公众号”。
也可打开单个公众号文章后点击“开始扫描最近 50 篇”。扫描期间保持微信前台；离开微信即暂停，回 DSH 可继续或停止。

扫描使用现有 SessionStore / EngineManager 启动独立会话；模型负责公众号主页、最新历史列表、
文章打开、返回、滚动和公开留言展开。操作通过本机 TLS ADB 执行，不依赖电脑转发或 Shizuku。
页面显示任务进度、执行记录、停止/继续入口和热榜。模型启动、网络或导航无进展时暂停；
手动继续保留目标账号、去重记录与已采集数据。

初始化当前文章仅用于识别账号，不占用最新 50 篇配额。每个扫描绑定账号标识，
最多允许 50 篇不同文章；其他公众号的文章拒绝入库。重复采集同一篇可更新数值、补充留言。
单号任务达到 50 篇后结束；批量任务达到该账号篇数上限后继续下一账号。列表结束、验证码、登录、权限或加载阻塞时如实记录状态。

## 数据真实性与排名

- 只接收本机 CDP 返回的固定提取脚本结果，模型无法提交自行生成的标题、数值或留言入库。
- 根据 mp.weixin.qq.com 的 page 类型、文章 URL、DOM 可见状态识别调试 socket/target，
  不把无线配对端口当成文章端口。扫描只读取当前可见文章 target。
- 使用文章 biz/mid/idx 或短链接路径散列去重，避免仅按标题合并文章。登录参数不入库。
- 保存阅读数、评论数原始显示值；缺失保持 null，不用已采集留言数量推算总评论数。
- “10万+”规范化为 100000 的下界，保留加号和原始文本；不能推断两篇 10万+ 的精确大小。
- 留言只包含页面实际加载、公开展示的内容，记录 not_loaded / loaded_partial / loaded_end /
  explicit_empty 状态；尚未加载不等于没有留言。不同微信版本可能需要调整页面选择器。每批提取最多 500 条已加载留言，返回下一批 offset，模型继续分批读取；这仍不代表服务器尚未加载的留言。
- 热榜按显示阅读数换算值降序、评论总数降序、采集时间降序排列，未知值排后。

## 存储

独立 Room 数据库 `databases/wechat-collection.db`，不更改原 DSH 会话数据库：

- articles：文章当前指标与采集时间；
- snapshots：每次采集的不可变原始结果，便于复核缺失值和计数变化；
- comments：按文章与留言 ID 去重的留言、昵称及点赞显示值；
- batches：批次、每号篇数、会话及状态；
- scans：扫描目标、篇数限额、所属批次、会话及任务状态；
- scan_articles：每个扫描实际采集到的不同文章。

快照和数据库保存在应用私有目录，沿用应用不备份策略。模型日志与截图由已有 DSH 会话机制保存。

## 执行边界

专用会话以 wechat_scan_ 开头，CapabilityHub 对其执行工具白名单：
`wechat_scan`、`wechat_article_collect`、`wechat_debug_targets`；engine 模式关闭通用 shell、文件、Web、
子代理和扩展工具。UI 导航只能打开微信、点击、滚动或返回，不接受模型提供的 shell 命令。
点击可用的界面树时拒绝“发送/点赞/关注/分享/支付”等明确控件；动态页面界面树不可用时返回截图及
原始尺寸，模型仍受阅读导航指令限制。网页和留言作为不可信数据处理，不作为任务指令。

停止先持久化状态并取消本会话正在执行的能力调用，不停止其他 DSH 会话。模型之后的导航/采集调用
会因任务非 running 被拒绝。单次运行最多一小时、60 次继续轮次；无采集进展则暂停。

JVM/Robolectric 测试覆盖显示值规范化、空值和下界排序、Room 快照与留言去重、账号/篇数/停止边界、
工具白名单、Android XML 解析兼容与点击控件过滤；JS 测试运行 Kotlin 中实际嵌入的提取脚本。
真机采集当前文章并显示热榜已经验证，标题“Deepseek-DSH的安卓版来了超越豆包”、公众号“子云之风”、阅读数75。
完整50篇以及不同微信页面样式的留言加载需要结合真实模型会话逐步验收，不能由单篇入库测试替代。

端口重发现：无线 TLS 连接被拒绝时重新寻找本机连接服务，排除 NSD 暂存的未监听端口，
验证新连接后才更新配置；系统无线调试关闭时不自动更改系统开关。

## 扫描期间保持 ADB 连接

一次开始/继续扫描只保留一条本机 ADB/TLS 传输。截图、输入、Shell、HTTP、CDP 依次使用独立的
ADB 逻辑通道，关闭逻辑通道不会断开传输；每个通道使用递增且不复用的 ID，过滤旧通道延迟到达的
关闭确认，并在提前关闭时排空在途数据。模型思考期间连接也保留，Socket 启用 TCP keepalive。

停止、完成、暂停、启动失败或运行超时会释放连接；停用本机 ADB 立即关闭。某个微信调试 socket
失效只报该服务错误，不丢弃健康传输。真实断线后下一次调用才重连；失败的点击不会自动重放。
重新配对、无线调试关闭或网络变化仍可能导致系统再次提示连接。

本改动减少的是反复建立 ADB 连接引起的系统通知，不更改系统通知设置；ROM 可能持续显示一条
“调试已连接”状态。已有文章和扫描去重记录保留，继续原任务即可使用长连接。

协议回归覆盖同连接内 Shell / DevTools 混用、提前关闭及在途数据、旧通道延迟确认、已失效
DevTools 服务、断线后下一次调用重连、不自动重放失败动作。定向 Android 测试共 34 项通过，含握手前取消时的 socket 释放。

Redmi K60 真机连续文章读取和状态检查：`connections_opened` 始终为 1，且 `tls: true`。
结束验证作用域后 `persistent: false, connected: false`。报告位于
`build/validation/adb-persistent-final.json` 和 `build/validation/adb-persistent-closed.json`。

## 从关注列表批量扫描

在微信打开“我关注的公众号”，再回 DSH 本机 ADB → 公众号采集与热榜，点击
“扫描我的关注公众号”。任务会切回微信并确认列表入口，逐个进入账号的历史文章，
每号采集最近最多 50 篇。请保持手机解锁，扫描时避免同时操作微信。

- 一次批量任务共用同一模型会话和 ADB 长连接；跨账号不主动断开 ADB。
- `begin_account` 从当前可见文章的 CDP 数据读取已验证的 biz 身份；只有昵称而没有可验证身份时拒绝绑定。
  同一批次相同 biz 不重复建立账号任务，当前账号未结束时拒绝切换账号写入。
- `finish` 结束当前账号；`finish_batch` 结束整个列表任务，存在运行中账号时拒绝结束批次。
  50 篇上限按账号单独执行，最后一篇留言分页结束后才自动完成。
- 列表虚拟滚动由模型结合截图和持久化进度操作，不能把一屏当作全部名单。
  账号不可访问可留下 `skipped` 记录，不生成零值文章；其名称是模型观察到的界面标签，未作为账号真实身份验证。
- 账号历史已到末尾标记完成；受阻保留部分结果。只有明确列表末尾才标记批次遍历完成，
  部分/跳过账号仍在任务页显示，不据此宣称全部文章采集成功。
- 停止、进程重启、两小时运行上限、120 轮继续上限、无采集进展、连接或模型异常均保留检查点。
  继续批次会恢复中断账号，保留已完成账号与文章去重记录；列表排序变化时仍需模型重新定位，无法保证快照式全量覆盖。

公众号热度统计按去重文章的最新阅读数合计降序、评论合计次序显示；未知读数不计入合计，
全缺失时显示未知，并显示阅读/评论各自覆盖篇数。“+”下界被标注，缩略读数仍为估算。
各账号样本数量、发布时间和采集时间可能不同，合计不能解释为相同统计窗口下的真实影响力排名。
点击账号可查看该账号前 200 篇文章热榜；可切回全部公众号查看跨账号文章排行。
原始采集快照仍保留，可用于后续增量统计，但本版本尚未提供按天阅读增长量排名。

独立采集数据库升级到 v2：新增 `batches` 表和 `scans.batchId` 索引，使用明确的 1→2 迁移，
不做破坏性重建。Robolectric 以冻结的 v1 schema 建库，验证文章、留言、快照、扫描去重记录均保留。

批量功能本轮验证：39 项 Android 定向测试、24 项 JS 测试通过；手机上实际从 v1 升级后保留
“子云之风”14 篇文章，阅读合计 571。真机结果见 `build/validation/wechat-followed-migration-device.json`。
关注列表起始界面已经截图确认；安装后的手机进入锁屏，批量导航和跨账号真实采集尚待解锁验收，
不能将数据库模拟测试表述为已完成真实关注列表遍历。

## 2026-11-02：真机补齐与小样本验收

- 批量任务开始和继续时先验证本机 ADB 可用，再写入运行状态并调用模型。未发现无线连接端口时提示
  检查系统无线调试和 WLAN，不再将 NSD 的内部 7 秒等待超时直接传给模型。
- `end` 改为对已验证、当前可见的公众号文章执行固定 `window.scrollTo`，不再依赖微信不响应的末尾按键。
  对隐藏页面不滚动，不接受模型提供的脚本。
- 微信新界面中，`#js_comment_bottom_num` 为公开留言总数；`comments` 导航只点击有正数的可见留言列表按钮，
  不点击“写留言”、回复或输入框。支持 `discuss_user_nickname`、留言 DOM ID 和 `js_cmt_container`。
- 每号篇数可在 1–50 中选择，默认 50。数量持久化到批次，继续旧批次不被当前设置改变；
  “历史批次”可查看最近 10 批并继续未完成批次，运行中批次优先展示。
- 独立数据库升级至 v3，2→3 迁移仅新增批次篇数字段、默认 50；v1 与 v2 冻结 schema 的迁移测试都保留旧数据。
